# SpellForge best-practices audit

Written 2026-10-10 at base commit 5e82a75 (mw-vtjxh4.26), package version 0.1.162. Docs only: no behaviour changed and no source file moved.

Why it exists. The Governor, Postern general, 2026-10-09 18:37Z: "don't forget all my apps they should all be on Jonathan a white you know my GitHub will you bring them up to best practices that we've spoken about". This is the first step for SpellForge: every line of the vault's PWA checklist (`seats/builder/pwa-best-practices/checklist.md`, 31 lines) and every rule the vault's changelog placed on 2026-10-09 (the six the story names, plus the two later anti-patterns), marked pass, fail or n/a with the evidence, and the failures turned into ranked stories.

How to read it. Rows C1 to C31 are the checklist lines in the checklist's own order; R1 to R6 are the rules added 2026-10-09; X1 and X2 are two later rules (2026-10-10). Status is `pass`, `fail` or `n/a`. A row cites `file:line` (every citation is checked to exist), a command with its output (section 4) or, for n/a, why the rule does not apply. A fail row names the smallest fix and a size: S is a few lines in one or two files; M is a story of several files with a new test; L is more than one story or a design decision, and is split when filed. Paths in backticks exist in the repo at the base commit; a file a fix would create is written in bold. The SpellForge repo holds one PWA (the React app at the repo root); `packages/bsv` is a library and `scripts/` are Node tools, so they carry no PWA row. Result: 39 rows, 5 pass (C22, C28, R2, R4, X1), 4 n/a (C20, C23, C24, R3), 30 fail. To re-run the checks on this file:

```sh
bash docs/check-best-practices-audit.sh
```
